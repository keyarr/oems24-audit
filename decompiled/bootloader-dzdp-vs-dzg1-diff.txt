INTERPRETATION
  The keymaster TA (keymint.mbn / keymaster.img) is BYTE-IDENTICAL between the
  DZDP device image and the DZG1 bootloader. So is every other TA (tz, vaultkeeper,
  tz_kg, engmode, hyp, xbl_config, cpucp, shrm, aop, bksecapp, storsec, tz_hdm, tz_iccc).
  The ONLY Secure World artifact that differs is devcfg.mbn (a ~5KB region at
  file offset 0x54442..0x55917, inside a packed fuse/security config blob).

  Therefore the patch for CVE-2026-21046 is NOT evidenced inside the keymaster TA
  from this artifact. Three possibilities, none confirmable from the bootloader tar:
    (1) the fix lives in the HLOS HAL (fkeymaster-service / fkeymaster-V1-ndk.so /
        fabric_crypto) which is NOT part of a bootloader tar -> need /vendor/bin pull;
    (2) the DZDP keymaster TA on the device was already post-fix (OTA-applied TA), so
        there is no vulnerable 'before' in this corpus -> need a pre-Jul-2026 TA;
    (3) the DZG1 build is not actually the SMR Jul-2026 fixed build.

  The devcfg delta is the single concrete change and is relevant to OEM-unlock /
  secure-state policy (fuses), but it is a config blob, not the fabricKeymaster TOCTOU.

CLASSIFICATION: UNCONFIRMED. The patch-diff did NOT confirm CVE-2026-21046 in the TA.
