  on the public test images. There is no evidence of anchor replacement
  or rotation in the CZD1 -> DZDP window.

  KEY INTE BUFFER SHRINK: the CZD1 type-1 item buffer is 0x108 (264)
  bytes instead of DZDP 0x200 (512). This is consistent with a
  smaller RSA modulus (RSA-2048 likely) and a smaller cert DER.
  EFFECT: the DZDP RSA-4096 256-byte recovery buffer mismatch
  documented in notes/findings.md does NOT exist in CZD1 because
  the buffer is now sized to match the (smaller) recovered output.
  If the issue is now structurally impossible, the CZD1 -> DZDP
  transition may have been a deliberate hardening pass; alternatively
  the issue remains but the type-1 cap was changed before this pass.
  This is a positive signal for memory-safety.

  KEY CRYPTO LIBRARY CHANGE: DZDP used a Samsung-internal RSA/EVP
  layer with a hard 0x200 type-1 cap. CZD1 uses BoringSSL/OpenSSL
  via EM_OPENSSL_FAILED error propagation. This is a routine
  dependency refresh and does not by itself indicate a security
  change, but it changes the set of attack surfaces that exist
  within this trustlet.
