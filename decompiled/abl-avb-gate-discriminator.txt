ABL AVB-GATE DISCRIMINATOR (experimento 1)
==========================================

PERGUNTA
  O ABL Samsung do S24 (DZDP) decide se roda a verificacao AVB 2.0 consultando a
  GPT em runtime — o padrao vulneravel de CVE-2026-24090
  (Is_VERIFIED_BOOT_2() -> GetPartitionIndex(L"vbmeta_a") / L"vbmeta"))?

  Referencia do codigo vulneravel (removido pelos commits b746f76e e 07665c08 em
  QcomModulePkg/Library/avb/VerifiedBoot.c, "edk2: Set VB2 status at compile time"):

      BOOLEAN Is_VERIFIED_BOOT_2 (VOID) {
        GetPartitionCount (&PtnCount);
        PtnIdx_a = GetPartitionIndex ((CHAR16 *)L"vbmeta_a");
        if (PtnIdx_a < PtnCount && PtnIdx_a != INVALID_PTN) return TRUE;
        else { PtnIdx = GetPartitionIndex ((CHAR16 *)L"vbmeta");
               if (PtnIdx < PtnCount && PtnIdx != INVALID_PTN) return TRUE; }
        return FALSE;                      // <- AVB 2.0 inteiro desligado
      }

  Mensagem do commit de correcao, literal:
    "This change aviods the risk of verified boot being disabled by attacker who
     gains the ability to modify the GPT partition table."

INTERPRETACAO
  "Device is unlocked, Skipping boot verification" NAO e um gate. E a mensagem
  emitida DEPOIS de 0x18f98 (verificacao) retornar, quando o byte
  is_device_unlocked da saida do AVB esta ligado. O branch e selecionado por
  [x19+0x438] == 2, e o unico escritor que pode produzir 2 e 0x159f4, que deriva
  de ldrb w8,[x20] — o bool is_device_unlocked do AvbSlotVerifyData.

  0x18f98 e chamado incondicionalmente: nao ha nenhum teste de presenca de
  particao, de contagem de particoes ou de indice de particao antes dele. O unico
  teste previo e 0x18e08, cuja falha vai para log de erro, nao para um caminho
  que pule a verificacao.

  Portanto o ABL Samsung nao possui Is_VERIFIED_BOOT_2() nem qualquer equivalente
  que consulte a GPT para decidir se verifica. CVE-2026-24090 nao se aplica.

  Cadeia confirmada ponta a ponta (efeito colateral util):
    avb_slot_verify (0x18f98)
      -> ops->read_is_device_unlocked  == 0x51048 (callback AVB)
      -> IsUnlocked                    == 0x41ed0 (ldrb w3,[x19,#0xe35])
      -> devinfo +0x0d
      <- GetEMBit(3) via SetUnlocked (0x42524, strb w19,[x1,#0xd])

VEREDITO
  CVE-2026-24090: NAO APLICAVEL — CONFIRMADO (negativo forte).
  Duas observacoes independentes concordam:
    (a) ausencia exaustiva de literais CHAR16 vbmeta no conjunto de 35 literais
        UTF-16 referenciados por codigo;
    (b) ausencia de qualquer teste de particao antes da chamada de verificacao
        em 0x18f98.
  Familia "chegar ao AVB por estrutura de disco nao assinada": fechada para a GPT.

  Mantem-se aberta a pergunta analoga para outras estruturas de disco nao
  assinadas consumidas antes de 0x18f98 — em particular UEFI variables
  (partitions_extra/uefivarstore.img), ainda nao analisadas.
