C. SetUnlocked() SIDE EFFECTS (RVA 0x424cc)
The function SetUnlocked writes only:
   - RVA 0x42524: strb w19, [x1, #0xd]  (live +0x0d)
   - RVA 0x4251c: str  w9,  [x8, #0xab0]  (UnlockCount, devinfo+0xc88)
   - RVA 0x42528: bl   0xff30            (persist full 0xcd0-byte DevInfo)
Callers of SetUnlocked (RVA 0x424cc):
   - dispatcher at RVA 0x41f88, called from RVA 0x99a4 (BLInitToken->GetEMBit->SetUnlocked)
   - the lock/unlock UI flow at RVA 0xacd2c (sets via UI button)
It does NOT modify any other boot state (no kernel cmdline change, no
verification flag change, no separate authentication variable).

D. INSTRUCTION-LEVEL HANDOFF SEARCH
ERET encoding 0xD69F03E0 (return from EL2 to EL1/EL0):
   count = 0
SVC #0 encoding 0xD4000001 (sync exception into EL1):
   count = 0
Interpretation: LinuxLoader does NOT use ERET or SVC to hand off to the kernel.
The actual handoff is the indirect call at RVA 0x1a1bc which loads a
function pointer from a runtime EFI protocol structure and branches to it.
That pointer is set up via the standard gBS / gRT boot services table.

Targeted search inside the BootLinux function (0x16e54-0x18500):
Conclusion: the post-BootLinux code uses gBS->StartImage-style
indirection (RVA 0x1a1bc / 0x1b340). There is no direct ERET or SVC in
the audited binary that bypasses the AVB result handling.

F. LOCKED vs UNLOCKED DIFF (after avb_slot_verify enters 0x140dc)

POST-VERIFY (0x96fc-0x9828 in main LinuxLoader):
   - on AVB result = ROLLBACK_ERROR (w8==3 && x0==0): slot swap path (0x9820)
   - on rollback / version errors: log and bail to 0x994c (or 0x9948)
   - on success: b 0x97b4 path; SetVerifiedBootState at 0x979c

     which is then propagated to NVRAM via gRT->SetVariable (no further gate)

THEN: EM sync (0x998c-0x99a4) -> SetUnlocked, then BootLinux (0x9820 -> 0x16e54)
