method
  full .text disassembly with capstone 5, md.skipdata=True. without skipdata the
  linear sweep stops at 0x456fc and produces false no-caller results.
  callee bounds via abl_string_xref.function_bounds plus manual prologue/ret
  checks. every claimed sink was read in instruction order. no string-only
  classification was used.
  correction to the prior map: the 16-function list in
  odin-usb-parse-before-verify-map.txt was produced by blob string containment,
  not by the real command switch. it does not describe the Odin USB dispatcher
  and is superseded by this report.

3. caveats and residual leads
  a. the state-9 copy is dead at the attacker-length call site. 0x58778 is
     only reached from 0x58460, which is the state != 0 and != 9 branch.
     the state-9 branch at 0x583ec goes to 0x5842c and then either logs and
     returns 3 (size <= 0x327) or takes the verify path (size > 0x327).
     neither path reaches 0x586f0. the only w5 == 9 call to 0x57d50 is
     0x58334 with a fixed 0x20 length.
  b. worker scheduling. 0xa6a0 has no direct bl/b or absolute pointer in
     .text/.data. the cmd 0x66 completion path at 0xca94 calls an indirect
     pointer loaded from [c61d0+0x28]; the string "ExtractThread" is
     referenced at 0xa944-0xa948. the worker invocation is inferred from
     that path, not proven by a direct static edge. a firmware build that
     never installs the c61d0 protocol would not reach it.
  c. PIT map. no .pit file exists in this repository. 0x8d3c0 is a partition
     id taken from the USB header at c60ac; 0x26a10 and 0x266d0 resolve it
     to a name through the PIT tables. the auth table at 0xa1c30 (0x50-byte
     entries, state at +4, name at +0x28) has state 9 for system, vendor,
     cache, userdata, omr, odm, hidden, carrier, persist, efs, sec_efs,
     product, dqmdbg, spu, prism, optics, metadata, super. state 11 covers
     pit, xbl, tz, abl, hyp, cpucp_dtb and the other bootloader entries.
     the branch taken is fixed by the resolved state, so this map decides
     which images reach 0x58460.
  d. residual lead 1, external protocol. 0x57e08 loads the
     protocol at [e49a0], then 0x57e2c calls [e49a0]+8 with x1=0x89cc8,
     x2=buffer base, w3=signature offset, x4=sp+8. the result is treated as 0x20
     bytes at 0x57ed0. if the callee writes w3 bytes to sp+8, the 0x40-byte
     stack region overflows. the callee is not in this PE. no local copy,
     inconclusive. the state-9 path calls the same protocol at 0x58224
     with x1=sp+8, x2=image, w3=len; the output is used as a 0x20-byte
     digest at 0x5831c. same external callee class, also inconclusive.
  e. residual lead 2, state-9 large image. 0x585c8 add x24,x22,w23,uxtw and
     0x58600 sub w2,w21,w23. if w23 > size, w2 underflows and 0x58040
     receives a huge length. 0x58040 forwards it to an external protocol at
     [e49a0]+0x18. OOB read/DoS lead, no local copy, inconclusive.
  f. pre-validation header and signature reads. 0x5ff10 calls 0x5fb00,
     which checks a 9-byte magic at buffer+u16[+8]+u16[+0xa]+0x300 and
     copies 0x100 bytes to e80094. the state-9 large path then copies
     0x100 bytes from buffer+u16[+8]+u16[+0xa] to e49c0 at 0x585a8.
     both reads happen before 0x58040 verifies the image. the source
     offsets are u16 fields from the usb image header and are not checked
     against the declared size. the state-9 gate only requires size >
     0x327, while the header copy at +0x300 reads 0x100 bytes, so up to
     0xd8 bytes past the declared size are read when the offsets are zero.
     destinations are fixed 0x100 buffers, so there is no write overflow.
     normal placement inside the 300 MB c6198 allocation keeps the reads
     in bounds; a small non-9 image at offset zero can point before the
     buffer. OOB read/DoS lead, inconclusive.

4. conclusion
  no confirmed pre-validation write overflow or attacker-sized allocation
  in the Odin USB parser. two fixed 0x100 header/signature reads run before
  verification, see caveat f. the USB dispatcher and the three main upload
  paths are bounded or verify before their write sinks:
    PIT upload <= 0x8000, verified at 0x63630 before write.
    XMIT <= 0x6400000, destination inside the 300 MB c6198 allocation.
    image table writes happen after 0x58350 success.
  the apparent 0x57d50 state-9 stack copy is dead at the attacker-length
  call site: 0x58778 is on the state-11 branch. the state-9 branch reaches
  0x57d50 only from 0x58334 with a fixed 0x20 length. the earlier stage2
  note that this copy was live was based on a partial branch read.
  the remaining cross-module leads are the non-9 protocol call at
  0x57e2c, which gets an attacker-controlled offset and a stack
  destination, and the state-9 large path that can pass an underflowed
  length to 0x58040. both callees are outside this PE; neither is a
  demonstrated bug.
  overall: no parser bug demonstrated. the prior negative verdict stands,
  now with the real dispatcher and the corrected state branch.
